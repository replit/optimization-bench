# Verifier-only checks

This is a new distinct-input definition, not a qualified reuse of the parked
repeated-request SQLite workload. Public and held-out derived databases contain
disjoint whole-country groups, original plant IDs, full original rows and
request identities. The authoring receipt records population and source hashes.

A scoring host must perform real pristine judge builds, complete public/held-out output
checks, native interfaces/state and the named unchanged upstream TCL selection.
Public A/A precedes held-out A/A; each timed unit must be at least one second,
have CI containing one and at most 3 pp full width, without repeated inputs.
Use the predeclared fail-only futility tooling. Unregistered
development A/A is diagnostic only. No sandbox run supports an official
speedup or admission claim.

The comprehensive v1.1 fuzz/mutation bar is explicitly pending; a passing A/A
alone cannot promote this task.

Suite units (ten besides the facets and ranked-documents units): held-out inputs are derived bodies listed in
`heldout.lock.json` with their derive recipes and raw upstream URLs/SHA-256 in
`heldout/manifest.json`. The bodies are stored in Git LFS under `heldout/files/` and are authenticated
against those SHA-256 values at scoring; each can also be rebuilt from its raw upstream files with
`environment/workload/driver/derive.py`, which fails closed on any byte difference.
Sources, licences and attributions for every held-out input are in `notices/HELDOUT-INPUTS.md`,
with the licence texts they need in `notices/`; public inputs are covered by
`environment/notices/SUITE-INPUTS.md`.
Database images exported by the CREATE INDEX and foreign-key units are judged by the
verifier's own CPython `sqlite3` (integrity check plus canonical row-dump digest), never the candidate
library.
